# 설치 안내 — ui-inspector 스킬 + MCP 서버

**이 파일을 읽는 클로드에게**: 아래 순서대로 설치하고, 마지막에 사용자에게 사용법과 **재시작 필요**를
알려주세요.

## 무엇인가

실행 중인 화면에서 **요소를 클릭하면 그 요소의 코드 위치·컴포넌트 이름·계산된 스타일·부모 구조·
UI/UX 용어를 즉시 받아** 클로드가 그 파일을 직접 고치는 도구입니다.
외부 LLM을 호출하지 않고 위치·스타일만 돌려주며, 판단과 수정은 클로드가 합니다.

해결하는 문제: "여기 여백 좀 늘려줘"라고 말할 때 **어느 파일 몇 번째 줄인지 사람이 찾아 알려주는 일**이 없어집니다.

## 설치 (1단계)

```bash
bash install.sh
```

두 가지를 합니다.

1. **스킬 복사** — `skill/ui-inspector/` → `~/.claude/skills/ui-inspector/`.
   같은 이름이 이미 있으면 **지우지 않고** `.bak-<날짜>`로 옮겨둡니다.
2. **MCP 서버 설치** — 공개 저장소 `github.com/beyondworks/UI-Inspector`를 `~/ui-inspector`로 clone →
   `servers`에서 `npm install`(수십 MB, 1~2분) → `claude mcp add -s user`로 등록.

경로를 바꾸려면 `UI_INSPECTOR_DIR=<경로>` / `CLAUDE_SKILLS_DIR=<경로>`를 앞에 붙입니다.
스킬만 먼저 넣고 싶으면 `bash install.sh --skill-only`.

**2단계가 실패해도 1단계는 그대로 둡니다.** 실패 메시지에 직접 실행할 명령이 찍히니 그걸 따르면 됩니다.

## 재시작 (2단계 — 건너뛰면 안 됩니다)

**클로드 코드를 재시작하세요.** MCP 서버는 재시작해야 붙습니다(스킬은 파일만 있으면 되지만, 이 스킬의
도구들은 MCP 서버가 있어야 동작합니다).

확인: 재시작 후 "프리뷰 띄워줘"라고 하거나 `preview_attach`를 호출해 봅니다.

## 사용자에게 알려줄 것 (3단계)

**쓰는 방법이 두 가지입니다.**

**(가) "이 부분" 지시 — 하나씩 고칠 때**
1. 이미 돌고 있는 개발 서버가 있으면 `preview_attach`, 없으면 `preview_start`로 프리뷰를 띄운다.
2. 프리뷰 **우하단 Inspector 토글**을 켠다.
3. 브라우저에서 요소를 클릭한다.
4. "이 부분 여백 늘려줘"처럼 말하면 클로드가 방금 클릭한 요소를 받아 파일을 고친다. HMR로 즉시 반영.

**(나) 어노테이션 — 여러 곳을 모아 한 번에 고칠 때**
1. 툴바에서 **Annotate**를 켜고 요소를 클릭해 코멘트를 남긴다(같은 요소에 여러 개 가능,
   **드래그하면 영역 안 요소들이 한 핀으로 묶인다**).
2. "핀 단 것들 반영해줘"라고 하면 클로드가 전부 읽어 순서대로 고친다.
3. 하나 고칠 때마다 브라우저 핀이 **초록 ✓로 실시간 전환**된다.
4. 어노테이션은 서버에 저장돼 새로고침·HMR에도 남는다.

트리거 문구: "인스펙터", "프리뷰 띄워줘", "이 부분 수정", "여기 색 바꿔", "핀 단 것들 반영해줘".

## 알아둘 것

- 코드 위치는 **`data-at` 속성이 주입된 프로젝트에서만** 자동으로 잡힙니다(Next.js·Vite React는 보통 자동).
  없으면 클래스·부모 구조로 파일을 찾아갑니다.
- `preview_attach`는 원본 개발 서버의 HMR을 유지하므로 **원본 파일을 그대로 고치면 됩니다.**
- 요소를 클릭하지 않은 상태에서 "이 부분"이라고 하면 선택 정보가 비어 있습니다 — 먼저 클릭해야 합니다.
- 필요 환경: Node 20+ , git. macOS·리눅스 기준입니다.
